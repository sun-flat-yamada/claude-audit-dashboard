# F-015 PR4: archived-snapshot comparison

Closes #116 (Work-Unit Issue, sub-issue of #42), Refs #42. Implements D-2 of `.devs/changes/2026-10-05_F015MultiTimePointSampleData/implementation_plan.md`: the `archived` state of `detail/compare/index.json`, and the integration tests that #42 requires ("comparison with archived snapshots"). E2E / axe additions and the docs close-out stay in PR5.

## User Review Required

> [!IMPORTANT]
> - The compare contract is NOT changed: `compareIndexSchema` already allows `state: 'archived'` (collectedAt / score / assessed `null`). No `schemaVersion` bump, `data/sample/` is expected to stay byte-identical.
> - The demo's synthetic archive listing (inventory only, ids without history) is deliberately not turned into `archived` compare points, so the public sample does not change.

> [!WARNING]
> - An archived point WITH a persisted summary is a normal `summary` point (the summary outlives the snapshot). Only archived ids without a summary become `archived` entries.

## Proposed Changes

### packages/core

#### [MODIFY] `src/application/presenters/archive-view.ts`

- `archivedSnapshotIds(entries)`: pure, the valid `<year>/<id>.json.gz` ids newest first (same validity rules as `summarizeArchiveEntries`).

#### [MODIFY] `src/application/presenters/time-point-summary.ts`, `detail-view.ts`

- `buildCompareIndex(summaries, now, limit, archivedIds)`: merges summary points and summary-less archived ids, newest first, one 90-point cap for both, deterministic. `DetailInput.archivedIds` feeds it; the index is `unavailable` only when there is neither a summary nor an archived id.

### packages/collector

#### [MODIFY] `src/main/detail.ts`

- `writeDetail` passes `archivedSnapshotIds(listing of the data directory)`. A supplied listing (demo) is inventory only.

### Tests

- `packages/core/src/application/__tests__/time-point-summary.test.ts`, `archive-view` tests: merge, dedupe, cap, determinism, `archivedSnapshotIds`.
- NEW `packages/collector/src/main/__tests__/compare-archived.test.ts`: B3 synthetic long history (> 365 days) judged snapshot by snapshot, `archive` with a short retention, summaries deleted in one scenario; (1) `archived` listing, (2) `restore` + `detail --snapshot` makes the point comparable, (3) diff and Markdown / CSV / JSON exports byte-identical to the never-archived run, (4) surviving summary keeps the pre-archive diff, (5) 90-point cap with live + archived, (6) B1 fixture-tenant round trip, (7) `checkDetailBundle` on the generated detail directory.
- Dashboard: a golden index (generated by the collector path and pinned by the collector test) feeds a component test of the archived guidance; the command names are checked against the root `package.json` scripts.
