# Storage & Data Routing Rules

## Fork-Safe Architecture

This project is designed to be **forked** by downstream enterprise organizations.
The `main` branch of upstream (`sun-flat-yamada/claude-audit-dashboard`) must contain **zero live data**.

### Branch Strategy

```
main              ← Code only. No audit data. Fork-safe.
gh-pages          ← Dashboard static assets (auto-generated by CI)
data/audit        ← Orphan branch. Audit snapshots & reports (per-fork)
```

### Data Storage Locations

| Data Type            | Storage                 | Branch                | Committed to main? |
| -------------------- | ----------------------- | --------------------- | ------------------ |
| Source code          | `packages/`             | `main`                | ✅ Yes             |
| Sample/demo data     | `data/sample/`          | `main`                | ✅ Yes             |
| Live audit snapshots | `data/snapshots/`       | `data/audit` (orphan) | ❌ Never           |
| Compliance reports   | `data/reports/`         | `data/audit` (orphan) | ❌ Never           |
| Dashboard JSON       | `data/dashboard.json`   | `data/audit` (orphan) | ❌ Never           |
| Collector state      | `data/state.json`       | `data/audit` (orphan) | ❌ Never           |
| Monthly reports      | `data/reports/monthly/` | `data/audit` (orphan) | ❌ Never           |
| Archived data        | `data/archive/`         | `data/audit` (orphan) | ❌ Never           |

### Why Orphan Branch?

1. **Fork Isolation** — When a downstream fork runs `Sync Fork`, only `main` code is synced. Audit data stays local to each fork.
2. **History Separation** — Audit data commits don't pollute code history or inflate repository size.
3. **Access Control** — Branch protection rules can restrict who writes to the data branch.
4. **Clean Upstream** — Upstream `main` is always clean, ready for `Sync Fork` with zero conflicts.
5. **Long-term Retention** — Data persists independently of code releases.

### Initialization

The `data/audit` orphan branch is auto-created on first collection run:

```bash
git switch --orphan data/audit
git commit --allow-empty -m "chore: initialize audit data branch"
git push origin data/audit
```

### Dashboard Build Pipeline

During dashboard build, the CI:

1. Checks out `main` for code
2. Checks out `data/audit` branch into `./data/` overlay
3. Builds dashboard with live data
4. Deploys to GitHub Pages

If the `data/audit` branch doesn't exist (fresh fork), sample data from `data/sample/` is used as fallback.

### Data Retention & Archival

- Raw snapshots: retained for configurable period (default: 365 days)
- Monthly reports: retained indefinitely
- Archived data: compressed older snapshots, retained indefinitely
- Anthropic Compliance API retains audit logs for 6 years, but this system stores independently for longer-term access

### fork:verify Script

The `npm run fork:verify` script ensures:

1. No live data files exist on `main` branch
2. `data/sample/` contains valid demo data
3. No secrets in tracked files
4. `.gitignore` properly excludes live data paths
