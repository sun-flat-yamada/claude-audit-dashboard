# Storage & Data Routing Rules

## Fork-Safe Architecture

This project is designed to be **forked** by downstream enterprise organizations.
The `main` branch of upstream (`sun-flat-yamada/claude-audit-dashboard`) must contain **zero live data**.

### Branch Strategy

```
main              ← Code and the synthetic sample only. No audit data. Fork-safe.
data/audit        ← Orphan branch. Audit snapshots, reports and state (per fork)
```

### Data Storage Locations

| Data Type            | Storage                                                 | Branch                | Committed to main? |
| -------------------- | ------------------------------------------------------- | --------------------- | ------------------ |
| Source code          | `packages/`                                             | `main`                | ✅ Yes             |
| Sample/demo data     | `data/sample/` (generated by `pnpm demo`)               | `main`                | ✅ Yes             |
| Live audit snapshots | `data/snapshots/<id>/<dataset>.json` + `manifest.json`  | `data/audit` (orphan) | ❌ Never           |
| Compliance reports   | `data/reports/compliance/<snapshot id>.json`            | `data/audit` (orphan) | ❌ Never           |
| Weekly / monthly     | `data/reports/{weekly,monthly}/` (md, html, csv, json)  | `data/audit` (orphan) | ❌ Never           |
| Dashboard JSON       | `data/dashboard.json` (DashboardView v2)                | `data/audit` (orphan) | ❌ Never           |
| Collector state      | `data/state.json` (cursors, projections, notifications) | `data/audit` (orphan) | ❌ Never           |
| Archived data        | `data/archive/<year>/<id>.json.gz`                      | `data/audit` (orphan) | ❌ Never           |

### Why Orphan Branch?

1. **Fork Isolation** — When a downstream fork runs `Sync Fork`, only `main` code is synced. Audit data stays local to each fork.
2. **History Separation** — Audit data commits don't pollute code history or inflate repository size.
3. **Access Control** — Branch protection rules can restrict who writes to the data branch.
4. **Clean Upstream** — Upstream `main` is always clean, ready for `Sync Fork` with zero conflicts.
5. **Long-term Retention** — Data persists independently of code releases.

### Initialization

All reads and writes of the branch go through `.github/scripts/data-branch.sh`:

```bash
.github/scripts/data-branch.sh restore            # copy data/ from data/audit (no-op before the first run)
.github/scripts/data-branch.sh save "<message>"   # mirror data/ to data/audit and push
```

The first successful `save` creates the orphan branch. `save` refuses to run without a prior `restore` in the same checkout (it mirrors deletions, e.g. archived snapshots), never copies `data/sample/`, and is serialized by the `audit-data` concurrency group shared by every writing workflow.

### Dashboard Build Pipeline

`deploy-pages.yml`:

1. Checks out `main`
2. Stages `packages/dashboard/public/data/dashboard.json`: from `data/audit` when the repository variable `PAGES_DATA_SOURCE=live`, otherwise from `data/sample/`
3. Builds with `STAGED_DATA=1` so `scripts/stage-data.mjs` keeps the staged file
4. Deploys to GitHub Pages

Locally, `pnpm dev` / `pnpm build:dashboard` stage `data/dashboard.json` when it exists (after `pnpm build:data`), else the sample. The SPA fetches `data/dashboard.json` relative to the Vite base path.

### Data Retention & Archival

- Raw snapshots: `retention.snapshotDays` (default 365), then `pnpm archive` moves them to `data/archive/<year>/` (gzip)
- Compliance, weekly and monthly reports: retained indefinitely
- Archived data: retained indefinitely
- Anthropic Compliance API retains audit logs for 6 years, but this system stores independently for longer-term access

### fork:verify Script

The `pnpm fork:verify` script ensures:

1. No live data paths are tracked on the code branch
2. `data/sample/dashboard.json` matches the published `DashboardView` contract and has `source: "demo"`
3. `data/sample/` contains only `example.*` e-mail addresses
4. No secrets in tracked files; `.gitignore` excludes `.env`, `node_modules`, `dist`; `.env.example` holds no real values
